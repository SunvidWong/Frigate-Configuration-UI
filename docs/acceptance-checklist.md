# 人工验收检查清单

本文档提供人工验收测试（E2E Acceptance）的详细步骤。在所有 Epic 完成后执行。

## 前置条件

- Docker 20.10+ 已安装
- Docker Compose v2+ 已安装
- 系统内存 >= 4GB
- 端口 9888, 5200-5229 未被占用

---

## AC-1: 品牌模板部署（无 ONVIF 网络）

**目标**: 验证在没有 ONVIF 网络的情况下，可以使用品牌模板成功部署实例。

### 测试步骤

- [ ] **AC-1-1** 启动父容器

```bash
cd docker
docker-compose up -d
```

验证容器启动成功：
```bash
docker ps | grep frigate-config-deploy
```

- [ ] **AC-1-2** 访问 WebUI

打开浏览器访问: `http://localhost:9888`

验证：
- ✅ 页面正常加载
- ✅ 界面显示中文
- ✅ 显示"创建实例"或"新建实例"按钮

- [ ] **AC-1-3** 步骤 1：硬件配置

填写表单：
- 实例名称: `test-hikvision`
- 硬件模式: 选择"CPU（通用）"
- Frigate 镜像: `stable`（默认）
- 时区: `UTC`

点击"下一步"

验证：
- ✅ 进入步骤 2
- ✅ 步骤指示器显示当前在"摄像头配置"

- [ ] **AC-1-4** 步骤 2：摄像头配置

选择"品牌模板"方式：
- 选择品牌: `海康威视`
- IP 地址: `192.168.1.100`（替换为实际摄像头 IP）
- 用户名: `admin`
- 密码: `your_password`（替换为实际密码）

验证：
- ✅ 自动生成主码流 URL: `rtsp://admin:your_password@192.168.1.100:554/Streaming/Channels/101`
- ✅ 自动生成子码流 URL: `rtsp://admin:your_password@192.168.1.100:554/Streaming/Channels/102`

（可选）点击"测试 RTSP"按钮：
- 如果测试成功：✅ 显示成功提示
- 如果测试失败：⚠️ 显示警告但允许继续

点击"下一步"

- [ ] **AC-1-5** 步骤 3：复核部署

验证配置摘要：
- ✅ 实例名称: `test-hikvision`
- ✅ 硬件模式: CPU（通用）
- ✅ 摄像头数量: 1
- ✅ 摄像头详情正确显示

点击"一键部署"按钮

等待部署完成（约 10-30 秒）

- [ ] **AC-1-6** 部署成功

验证：
- ✅ 显示"部署成功"消息
- ✅ 显示实例 UI URL: `http://localhost:5200`
- ✅ 显示容器 ID

- [ ] **AC-1-7** 访问 Frigate UI

在浏览器新标签页中访问: `http://localhost:5200`

验证：
- ✅ Frigate UI 正常加载
- ✅ 左侧菜单显示摄像头列表
- ✅ 点击摄像头可以看到实时画面（如果 RTSP 配置正确）

- [ ] **AC-1-8** 验证中文界面

返回配置 UI (`http://localhost:9888`)

验证所有界面文案为中文：
- ✅ 按钮文案：「创建实例」、「下一步」、「一键部署」等
- ✅ 表单标签：「实例名称」、「硬件模式」、「摄像头配置」等
- ✅ 错误提示：如有错误，应显示中文提示

**预期结果**: ✅ 部署成功、UI 完整、摄像头连接正常

## AC-2: ONVIF 双镜头配对（有 ONVIF 网络）

**目标**: 验证 ONVIF 自动发现和双镜头摄像机的主/子流配对功能。

**前置条件**: 需要局域网内有支持 ONVIF 的摄像头，最好是双镜头摄像机（如 Reolink Duo）。

### 测试步骤

- [ ] **AC-2-1** 启动 ONVIF 扫描

在步骤 2（摄像头配置）中：
- 选择"ONVIF 扫描"方式
- 填写摄像头用户名和密码
- 点击"扫描局域网设备"

等待扫描完成（5-10 秒）

- [ ] **AC-2-2** 发现双镜头摄像机

验证：
- ✅ 扫描结果列表显示发现的设备
- ✅ 设备信息包含：品牌、型号、IP 地址
- ✅ 如果是双镜头摄像机（如 Reolink Duo），显示"2 个通道"

- [ ] **AC-2-3** 验证 profiles 分组

查看设备详情（点击展开）：
- ✅ 显示 2 个 VideoSource（双镜头）
- ✅ 每个 VideoSource 下有多个 profiles
- ✅ 总共约 4 个 profiles

- [ ] **AC-2-4** 验证主/子流配对

自动配对结果：
- ✅ 每个通道都配对了主码流和子码流
- ✅ 子码流像素数 < 主码流像素数 * 0.6
- ✅ 显示分辨率信息（如主流 2560x1440，子流 896x512）

- [ ] **AC-2-5** 生成摄像头配置

验证：
- ✅ 自动生成 2 个摄像头配置
- ✅ 摄像头名称为: `reolink-duo-ch1`, `reolink-duo-ch2`（或类似）
- ✅ 每个摄像头都有主码流和子码流 URL

- [ ] **AC-2-6** RTSP 测试失败场景

（可选）故意填写错误的密码触发 RTSP 测试失败：
- ✅ 显示警告: `[WARN][RTSP_TEST_FAIL]`
- ✅ 显示错误分类（鉴权失败/超时/路径错误）
- ✅ 提供修复建议

- [ ] **AC-2-7** 允许继续部署

即使 RTSP 测试失败：
- ✅ "下一步"按钮仍然可用
- ✅ 可以继续到步骤 3

修正配置后重新测试或直接继续部署

- [ ] **AC-2-8** 双摄像头显示

部署成功后，访问 Frigate UI:
- ✅ 左侧菜单显示 2 个摄像头
- ✅ 两个摄像头都可以显示实时画面
- ✅ 摄像头名称正确

**预期结果**: ✅ 双镜头正确配对、RTSP 失败仅警告不阻断部署

## AC-3: 多实例并存与克隆

**目标**: 验证多实例部署、端口自动分配、克隆和蓝绿部署功能。

### 测试步骤

- [ ] **AC-3-1** 部署第 2 个实例

返回 Dashboard，点击"创建实例"

配置第 2 个实例：
- 实例名称: `backyard`
- 硬件模式: CPU
- 摄像头: 添加一个摄像头（使用品牌模板或 ONVIF）

点击部署

- [ ] **AC-3-2** 验证端口分配

验证：
- ✅ 第 1 个实例（`test-hikvision`）端口: 5200-5209
- ✅ 第 2 个实例（`backyard`）端口: 5210-5219
- ✅ 两个实例 WebUI 都可访问：
  - `http://localhost:5200`
  - `http://localhost:5210`

- [ ] **AC-3-3** 验证实例同时运行

在 Dashboard 中：
- ✅ 显示 2 个实例卡片
- ✅ 两个实例状态都显示"运行中"
- ✅ 显示容器 ID（前 12 位）

访问两个实例的 Frigate UI，验证都正常工作

- [ ] **AC-3-4** 停止一个实例

在 Dashboard 中，点击第 1 个实例（`test-hikvision`）的"停止"按钮

验证：
- ✅ 第 1 个实例状态变为"已停止"
- ✅ 第 2 个实例（`backyard`）仍然显示"运行中"
- ✅ 访问 `http://localhost:5210` 仍然可用

- [ ] **AC-3-5** 克隆实例

点击第 2 个实例（`backyard`）的"克隆"按钮

填写新实例名称: `backyard-new`

修改摄像头配置：
- 修改摄像头 IP 或其他参数
- 修改时区为 `Asia/Shanghai`

点击部署

- [ ] **AC-3-6** 验证克隆的实例

验证：
- ✅ 新实例 `backyard-new` 部署成功
- ✅ 端口分配: 5220-5229（自动顺延）
- ✅ 访问 `http://localhost:5220` 可用
- ✅ 配置已修改（摄像头 IP、时区等）

- [ ] **AC-3-7** 删除旧实例

在 Dashboard 中，点击旧实例（`backyard`）的"删除"按钮

确认删除

验证：
- ✅ 旧实例从列表中消失
- ✅ 新实例（`backyard-new`）仍然运行中
- ✅ 访问 `http://localhost:5220` 仍然可用

- [ ] **AC-3-8** 验证端口块释放

创建第 4 个实例

验证：
- ✅ 可以分配到已释放的端口块（5210-5219）
- ✅ 或自动顺延到下一个可用块

**预期结果**: ✅ 多实例部署、克隆、删除均正常工作

## AC-4: 错误码验证

**目标**: 验证所有错误码显示中文描述和修复建议。

### 测试步骤

- [ ] **AC-4-1** 触发 `[ERROR][DOCKER_SOCKET]`

**操作**：修改 `docker/docker-compose.yml`，注释掉 Docker socket 挂载：

```yaml
# volumes:
#   - /var/run/docker.sock:/var/run/docker.sock
```

重启父容器：
```bash
docker-compose restart
```

查看日志：
```bash
docker logs frigate-config-deploy
```

**验证**：
- ✅ 显示错误: `[ERROR][DOCKER_SOCKET] 未挂载 /var/run/docker.sock`
- ✅ 显示修复建议: `请在 docker-compose.yml 中添加 volumes: ...`
- ✅ 容器退出（快速失败）

**修复**：恢复 Docker socket 挂载，重启容器

- [ ] **AC-4-2** 触发 `[ERROR][DOCKER_DAEMON]`

**操作**：停止 Docker daemon（需要系统权限）

```bash
# macOS
# （通过 Docker Desktop 停止）

# Linux
sudo systemctl stop docker
```

启动父容器

**验证**：
- ✅ 显示错误: `[ERROR][DOCKER_DAEMON] Docker daemon 不可达`
- ✅ 显示修复建议: `确认 Docker 服务正在运行 ...`

**修复**：启动 Docker daemon

- [ ] **AC-4-3** 触发 `[ERROR][IMAGE_PULL]`

**操作**：在步骤 1 中填写不存在的镜像 tag

- 镜像标签: `nonexistent-tag-999`

尝试部署

**验证**：
- ✅ 显示错误: `[ERROR][IMAGE_PULL] 镜像拉取失败且本地无缓存`
- ✅ 显示修复建议: `使用已存在的镜像标签（如 stable）...`

**修复**：使用 `stable` tag

- [ ] **AC-4-4** 触发 `[ERROR][PORT_CONFLICT]`

**操作**：手动占用端口 5200

```bash
# 启动一个占用 5200 端口的容器
docker run -d -p 5200:80 nginx:alpine
```

尝试部署第一个实例

**验证**：
- ✅ 端口冲突自动顺延到 5210-5219
- ✅ 或显示警告: `[WARN][PORT_CONFLICT] 端口已被占用，自动顺延`

**清理**：停止占用端口的容器

- [ ] **AC-4-5** 触发 `[ERROR][NAME_INVALID]`

**操作**：在步骤 1 中填写非法的实例名称

尝试以下名称：
- `FrontDoor`（包含大写）
- `cam_01`（包含下划线）
- `ab`（过短，<3 字符）

**验证**：
- ✅ 显示错误: `[ERROR][NAME_INVALID] 名称格式无效`
- ✅ 显示格式要求: `必须符合格式：小写字母开头，仅包含小写字母、数字和连字符，长度 3-32 字符`
- ✅ "下一步"按钮禁用

**修复**：使用合法名称 `front-door`

- [ ] **AC-4-6** 触发 `[WARN][RTSP_TEST_FAIL]`

**操作**：在步骤 2 中故意填写错误的 RTSP 信息

- 错误的密码
- 错误的 IP 地址
- 错误的 RTSP 路径

点击"测试 RTSP"

**验证**：
- ✅ 显示警告: `[WARN][RTSP_TEST_FAIL] RTSP 连通性测试失败`
- ✅ 显示错误分类:
  - 鉴权失败 (401): `[RTSP_AUTH_FAIL]`
  - 连接超时: `[RTSP_TIMEOUT]`
  - 路径错误: `[RTSP_INVALID_URL]`
- ✅ 显示修复建议
- ✅ 允许继续部署（"下一步"按钮可用）

**预期结果**: ✅ 所有错误码显示中文描述与修复建议，可自助解决

## 验收通过标准

- ✅ AC-2: ONVIF 双镜头配对成功（如有条件）

## 已知限制

1. RTSP 测试失败不阻断部署（设计如此）
2. 首次拉取 Frigate 镜像可能需要较长时间
3. 某些摄像头品牌的 ONVIF 实现可能不完整
4. 硬件加速（NVIDIA/Hailo）需要额外配置
